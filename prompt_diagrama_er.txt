Actúa como un Arquitecto de Base de Datos y Administrador DBA Experto. Tu tarea es generar el código Mermaid para un Diagrama de Entidad-Relación (Entity-Relationship Diagram) sumamente detallado que modele la base de datos de mi sistema "Shopify Credit App".

El sistema fue recientemente refactorizado para cumplir con la Tercera Forma Normal (3NF), eliminando columnas redundantes y dependencias transitivas.

A continuación, te detallo las tablas exactas de la base de datos, sus columnas principales y cómo se relacionan. Usa esta información al pie de la letra para construir el diagrama:

**Tablas y Columnas Principales:**

1. **merchants** (Comerciantes)
   - `id` (PK, UUID)
   - `shop_domain` (String, Único)
   - `created_at` (DateTime)

2. **merchant_payment_settings** (Configuración de métodos de pago extraída en 3NF)
   - `id` (PK, Integer)
   - `merchant_id` (FK, UUID)
   - `payment_method` (String, Ej: Zelle, Pago Móvil)
   - `settings` (JSONB, Detalles de la cuenta)
   - `is_active` (Boolean)

3. **customers** (Clientes asociados a un comercio)
   - `id` (PK, Integer)
   - `merchant_id` (FK, UUID)
   - `shopify_customer_id` (String)
   - `full_name` (String)
   - `favorable_balance` (Numeric, Saldo a favor)

4. **credits** (Créditos otorgados a los clientes)
   - `id` (PK, Integer)
   - `customer_id` (FK, Integer)
   - `total_amount` (Numeric)
   - `balance` (Numeric, Saldo restante)
   - `status` (Enum: EMITIDO, EN_PROGRESO, PAGADO, etc.)

5. **credit_items** (Productos financiados en un crédito específico)
   - `id` (PK, Integer)
   - `credit_id` (FK, Integer)
   - `product_name` (String)
   - `quantity` (Integer)
   - `unit_price` (Numeric)

6. **credit_installments** (Cuotas generadas para pagar un crédito)
   - `id` (PK, Integer)
   - `credit_id` (FK, Integer)
   - `number` (Integer, Número de cuota)
   - `amount` (Numeric)
   - `due_date` (Date)
   - `status` (Enum: PENDIENTE, PAGADA, VENCIDA)

7. **payments** (Pagos realizados y aprobados/rechazados)
   - `id` (PK, Integer)
   - `credit_id` (FK, Integer)
   - `amount` (Numeric)
   - `reference_number` (String, Único)
   - `bank_name` (String)
   - `status` (Enum: APROBADO, EN_REVISION, RECHAZADO)

8. **payment_installments** (Tabla intermedia Muchos-a-Muchos para 3NF)
   - `payment_id` (PK/FK, Integer)
   - `installment_id` (PK/FK, Integer)
   *(Relaciona un pago con las cuotas específicas que está cubriendo)*

9. **payment_tokens** (Tokens de un solo uso para links de pago públicos)
   - `id` (PK, Integer)
   - `payment_id` (FK, Integer, Relación 1:1 con un payment EN_REVISION)
   - `merchant_id` (FK, UUID)
   - `token` (String, UUID)

10. **payment_proofs** (Comprobantes cargados por el cliente desde el portal público)
    - `id` (PK, Integer)
    - `token_id` (FK, Integer)
    - `reference_number` (String)
    - `amount` (Numeric)
    - `status` (Enum: PENDIENTE, REVISADO)
